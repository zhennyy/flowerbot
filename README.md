# 🌷 «Флёр» — цветочный магазин в Telegram

Telegram-бот с витриной (Mini App): каталог с фото, размеры S/M/L, поштучные цветы, допы к заказу,
доставка по расстоянию от пл. Восстания, онлайн-оплата ЮKassa, фото букета на согласование,
отзывы, напоминания о датах и админка для флориста прямо в Telegram.

## Что понадобится

**Node.js 22.12+** (`node -v` покажет версию; в `.nvmrc` — 22). После `npm install` сам сгенерируется клиент базы (Prisma) — отдельно ничего запускать не нужно.

## Как это устроено

`index.js` — точка входа: проверяет `.env` (без `BOT_TOKEN` или `WEBAPP_URL` сразу скажет, чего не хватает), готовит базу,
запускает сервер витрины, бота и фоновые задачи. Всё остальное — в `src/`, каждый механизм в своей папке:

| Папка | Что внутри |
|---|---|
| `config/` | чтение и проверка `.env` |
| `database/` | подключение к SQLite через Prisma, миграции, стартовый каталог |
| `catalog/`, `pricing/` | букеты, поштучные цветы и допы; цены заказа — только из базы |
| `orders/` | заказы и склад (`index.js`), тексты чека и статусов (`texts.js`), смена статуса с сообщением покупателю (`status.js`) |
| `calendar/` | дата и час по Москве, интервалы доставки, выходные и лимит заказов на интервал |
| `delivery/` | расчёт доставки по адресу (геокодер OpenStreetMap, зоны по городу, километры по Ленобласти) |
| `payments/` | запросы к ЮKassa (`yookassa.js`) и оплата заказа: платёж, уведомление, автоотмена, поздняя оплата (`index.js`) |
| `chat/` | переписка покупатель ⇄ флорист (`messages.js` — история для вкладки «Чаты») |
| `bouquet-photo/` | фото готового букета на согласование и ожидание ответа |
| `reviews/`, `reminders/`, `summary/` | отзывы после доставки, напоминания о поводах через год, сводка «что везём сегодня» |
| `notifications/` | «заказ принят», «новый заказ», «заканчивается на складе» |
| `schedulers/` | фоновые задачи раз в минуту |
| `settings/`, `owner/`, `backup/` | настройки магазина, кто владелица, резервная копия ZIP-архивом |
| `bot/` | Telegram-бот: `index.js` собирает обработчики из `handlers/` (старт, статусы, мои заказы, связь с флористом, фото букета, отзывы, напоминания, сводка), `keyboards.js`, `links.js`, `waiting.js` |
| `server/` | Express: API витрины и админки, вебхук ЮKassa, фото (`photos.js`), подпись Telegram и ограничение частоты (`auth.js`) |

Каждый HTTP-маршрут — своя папка в `src/server/routes/`: `shop` (каталог, доставка, интервалы, «Мои заказы»), `checkout` (оформление),
`yookassa` (вебхук оплаты), `admin-products`, `admin-orders`, `admin-chats`, `admin-stats`, `admin-settings` (админка):

```
src/server/routes/checkout/
  index.js       — маршруты
  validation.js  — проверка входящих данных (middleware перед маршрутом, кладёт результат в request.validated)
  test.js        — тесты этого маршрута
```

Адреса API и поля JSON — те же, что раньше: витрина и админка работают без изменений.
Ошибки в маршрутах ловит общий обработчик: наружу уходит короткий JSON, подробности — только в лог.

### Мини-приложение

Витрина (`public/index.html`) и админка владелицы (`public/admin.html`, `/admin` в боте) — без сборщика: браузер грузит ES-модули, сервер отдаёт папку `public/` как есть (HTML, CSS и JS — с `Cache-Control: no-cache`, чтобы после обновления не смешались старые и новые файлы).

```
public/
  index.html, admin.html — только разметка; подключают styles/*.css и scripts/<страница>/main.js
  styles/       — theme.css (цвета, светлая/тёмная тема) + shop/ и admin/: по файлу на раздел, desktop.css — для ноутбука
  scripts/
    shared/     — Telegram SDK, делегирование кликов (data-action), экранирование HTML, рубли и склонения
    shop/       — витрина: main.js, state.js, api.js, navigation.js; catalog/, cart/, checkout/, orders/
    admin/      — админка: main.js, api.js, dates.js, photo-files.js; orders/, chats/, products/, stats/, delivery/
  photos/       — фото букетов из проекта
```

Кнопки в разметке помечены `data-action="…"`; обработчики регистрируются по имени, слушатель кликов один на страницу. Проверка в браузере: `npm run test:ui` (Playwright на временной базе, подменённый Telegram; скриншоты всех экранов покупателя и владелицы, сценарии «корзина → заказ → „Мои заказы“» и «смена статуса, правка букета»; `-- --compare <папка>` сравнивает скриншоты с прошлым прогоном попиксельно).

### База данных

Работа с базой — через ORM [Prisma](https://www.prisma.io) (SQLite): запросы пишутся на JavaScript, без SQL.

```js
const myOrders = await database.order.findMany({ where: { user_id: userId }, orderBy: { id: 'desc' }, take: 30 });
```

- `prisma/schema.prisma` — схема всех таблиц (имена полей = колонки в базе).
- `prisma/migrations/*.sql` — изменения структуры; применяются сами при запуске, каждая один раз (учёт — в таблице `_app_migrations`).
  `001_baseline.sql` — ровно та схема, которая уже есть на сервере (версия 10 старого `db.js`), поэтому рабочая база
  обновляется без изменений, данные остаются на месте.
- База — `shop.db` в `DATA_DIR` (на сервере `/data/flowerbot/shop.db`), фото из админки — `DATA_DIR/uploads`; без `DATA_DIR` — в папке проекта.
- Клиент Prisma генерируется после `npm install` (`npm run db:generate` — вручную).
- Заказ и списание остатков выполняются вместе — в `runInTransaction(...)`.

### Проверка

```bash
npm test
```

65 автотестов: витрина (каталог, доставка, интервалы, «Мои заказы»), оформление заказа с проверкой даты и интервала по Москве,
остатки, вебхук ЮKassa (сумма, повтор уведомления, чужие платежи, автоотмена и поздняя оплата), админка (букеты, фото, заказы,
чаты, статистика, настройки, резервная копия), миграция старой базы и сам бот в чате — через подставные Telegram, ЮKassa и геокодер, без сети.
Тесты лежат рядом с кодом — файл `test.js` в папке модуля или маршрута; `npm test` находит их сам.

`npm run test:ui` — проверка мини-приложения в браузере (нужен Chromium для Playwright), в `npm test` не входит.

## Запуск на своём компьютере

1. `npm install`
2. Скопировать `.env.example` в `.env` и заполнить
3. Для теста в Telegram нужен HTTPS-адрес: в одном терминале `ngrok http 3000`, адрес вписать в `WEBAPP_URL`
4. В другом терминале `npm start`

## Работа 24/7 на своём сервере (VPS)

Бот работает на собственном сервере Ubuntu вместе с остальными проектами BotForAll.
Установка сервера описана в [BotForAll/deploy/README.md](https://github.com/zhennyy/botforall/blob/main/deploy/README.md).

| Что | Где |
|---|---|
| Код | `/opt/bots/flowerbot` |
| База и фото | `/data/flowerbot` (переменная `DATA_DIR`) — обновления их не трогают |
| Адрес витрины | `https://fleur.botforall.ru` (nginx + HTTPS, порт 3002) |
| Резервная копия | каждую ночь в `/var/backups/botforall`, хранится 14 дней |

1. **Ключи:** `bfa env flowerbot` → вписать `BOT_TOKEN`, `OWNER_ID`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`,
   `WEBAPP_URL=https://fleur.botforall.ru`, `DATA_DIR=/data/flowerbot`.
   Если сервер в России — ещё `TELEGRAM_API_ROOT` (адрес посредника для Telegram).
2. **Запуск:** `bfa start flowerbot`, проверить `bfa logs flowerbot` — строки `🤖 Бот запущен` и `🌐 Витрина…`.
3. **Один бот — одно место:** на ноутбуке бота с тем же токеном не запускать (иначе `409 Conflict`).
4. **ЮKassa** → Интеграция → HTTP-уведомления → `https://botforall.ru/yookassa-webhook`,
   события `payment.succeeded` и `payment.canceled`. Сервер сам разошлёт уведомление всем магазинам,
   а каждый бот проверит платёж в ЮKassa и возьмёт только свой.
5. **Обновление** после изменений в коде: `git push`, затем на сервере `bfa update`.
6. Проверить в Telegram: `/start`.
